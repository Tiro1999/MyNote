# Glossary

Binding for code, comments and docs (`.claude/rules/core.md` §3). Persisted names are the on-disk truth and never change; unclear names get a `NAMING-CHECK` marker.

## Notebook structure

| Term (UI) | Code | Files / persisted | Notes |
|---|---|---|---|
| Notebook | `Notebook` | `notebooks.json` (array of notebooks); folder `<notebookId>/` | Top level. Fields `id`, `name`, `color`, `sections`. |
| Manifest | `MANIFEST_PATH`, `parseNotebooks`, `loadNotebooks`, `saveNotebooks` (`notebook`) | `notebooks.json` | The whole notebook tree in one file; every tree change rewrites all of it. Loading checks ids and field types, fills missing `sections`, `pages` and `children` with `[]` and keeps unknown fields. A repeated notebook, chapter or page id is rejected, compared without case; the notebook id `finance` is reserved, in any case, because that folder holds the finance data. A failed check makes it a corrupt file. |
| Chapter | `Section` | `sections` (in a notebook), `sectionId` (in a page); folder `<notebookId>/<sectionId>/` | UI says Chapter, code and files say section. Avoid: Section in UI text. |
| Page | `PageMeta` | `pages` (in a chapter); `<notebookId>/<sectionId>/<pageId>/page.json` | Tree entry only; the content is in `page.json`, written first by the page's first content save. |
| Subpage | `PageMeta` | `children` (recursive); folder inside the parent page folder | Same type as a page; its `sectionId` stays the chapter id. |
| Collapsed state | `collapsed` | `collapsed` on chapter and page (optional) | Sidebar fold state, saved in `notebooks.json`. |
| Chapter note | `ContentRef` with `kind: 'section'` | `<notebookId>/<sectionId>/page.json` | The canvas a chapter holds itself. Its persisted `pageId` is the section id. |
| Content ref | `ContentRef { kind, id }`, `ContentKind`, `contentPath`, `resolves` | not persisted | `ContentKind` is `'section'` or `'page'`. Points at the open chapter note or page (store field `selection`); a tree change clears a selection that no longer resolves in the same store update. Avoid: `activeContentKind`, `activeContentId`, `activeSectionId`. |
| Notebook folder | `dataRoot`, `openFolder`, `openError` | folder that holds `notebooks.json` | UI "Notebook Folder"; renderer `dataRoot`; main "data root", set only by the folder dialog. A folder without a manifest opens empty; a corrupt manifest sets `openError`, keeps `dataRoot` null and writes nothing. |
| Id | `ID_PATTERN`, `isValidId`, `newId` | `id`, `sectionId`, `ledgerId` (also folder and file names) | Must match `/^[A-Za-z0-9_-]{1,64}$/` wherever it becomes a path segment. Folder names ignore case on Windows and macOS, so two ids that differ only in case count as the same id. |

## Canvas and editor

| Term (UI) | Code | Files / persisted | Notes |
|---|---|---|---|
| Canvas | `CanvasView` | `page.json`: `pageId`, `elements` (`PageContent`) | Free-form surface of one chapter note or page. Pan and zoom are not saved. It draws the text boxes only and shows "Double-click anywhere to add a text box" only when the page has no element at all (not while loading, not when it holds only foreign elements); a load error replaces it with red text. |
| Page content | `PageContent`, `parsePageContent`, `emptyContent` (`canvas`) | `page.json`: `pageId`, `elements` | Loading checks what rendering relies on: `elements` is a list, each element has a string `id` and `type`, a text box has finite numeric `x`, `y`, `width`, `height`, `zIndex` and an object `content`. It fills a missing `elements` with `[]` and a missing `pageId` with the content id, and keeps unknown fields on the page and on each element; a failed check makes it a corrupt file. |
| Content store | `useContentStore`, `startContentSync`, `flushContent`, `SAVE_DELAY_MS` (`canvas`) | `page.json` of the selection | Holds the open content (`ref`, `path`, `content`, `error`) and follows a changed `selection`, not a change of the tree alone; a load overtaken by a later selection is dropped. Selecting the open content again reloads it only after a failed load. A missing file opens empty and is created by its first save; a corrupt one sets `error`, keeps `content` null and is never saved. A save goes to the path loaded with its content: `addElement` and `deleteElement` at once, `commitElement` 400 ms after the last commit, `updateElement` never. An id that no text box has changes and saves nothing. A switch sends the pending save at once, or drops it when the old content was deleted. On window close the pending save is sent, and the close waits while text is still queued behind an in-flight write; a second close during that wait passes, so a stalled write cannot trap the window. |
| Canvas element | `CanvasElement` | `elements[]`: `id`, `type`, `x`, `y`, `width`, `height`, `zIndex` | `TextBoxElement` or `ForeignElement`. Avoid: `AnyCanvasElement`, `ImageElement`, `FileElement`. |
| Text box | `TextBoxElement`, `TextBox`, `newTextBox` | `type: 'textbox'`, `content` (TipTap JSON) | One TipTap editor per text box. A double-click on the empty canvas creates one (320 x 200, `zIndex` = highest + 1) at the pointer. It is edited while focused; a click focuses it and a click elsewhere ends that. |
| Foreign element | `ForeignElement` | `elements[]` entry with another `type` (`image`, `file`) | Kept and saved, never rendered. |
| Viewport | `Viewport { panX, panY, zoom }`, `useViewport`, `DEFAULT_VIEWPORT` (`canvas`) | not persisted | Pan (screen pixels) and zoom of one canvas. The surface is drawn at `translate(panX, panY) scale(zoom)`, so a point relative to the top-left corner of the canvas maps to the canvas by `(point - pan) / zoom`. Starts at pan 40, 40 and zoom 1; Reset returns there. Zoom runs from 0.2 to 3 and is not anchored at the pointer. |
| Canvas gestures | `wheelAction`, `wheelUpdate`, `isPanGesture` (`canvas`) | – | The wheel on the empty canvas pans; Ctrl or Meta + wheel zooms, also over a text box; the plain wheel over a text box scrolls that box. Alt + left drag and middle drag pan. A double-click creates a text box only on the empty surface, not on a box, the minimap or the zoom controls. |
| Canvas geometry | `geometry.ts` (`canvas`) | – | Pure coordinate maths without React: `screenToCanvas`, `visibleRect`, `intersects`, `cull`, `movedBox`, `resizedBox`, `contentBounds`, `minimapTransform`, `nextZIndex`. A `Rect` is `{ x, y, width, height }` in canvas units; the `margin` of `visibleRect` is a share of the visible size. |
| Culling | `cull`, `CULL_MARGIN` (`canvas`) | – | Only text boxes within half a screen of the visible area are mounted (touching counts); the focused box always is. Avoid: virtualization. |
| Drag and resize | `usePointerDrag` (`ui`), `movedBox`, `resizedBox`, `dragOffset`, `DRAG_THRESHOLD`, `TextBoxPatch` | `x`, `y`, `width`, `height` of the element | A press on an unfocused box turns into a drag after 3 px, so a plain click still reaches the buttons and links inside a block; `dragOffset` gives the way from the press to the first move past 3 px, which the drag adds to its deltas, so the box stays under the pointer from the press on. Screen deltas are divided by the zoom; the minimum size is 120 x 60. `updateElement` follows the pointer without saving, `commitElement` runs once on pointer up. A box with unreadable content moves and resizes but keeps its stored `content`. |
| Minimap | `Minimap`, `minimapTransform`, `toMinimap`, `fromMinimap` (`canvas`) | – | 180 x 120 overview of the text boxes and the visible area, with 60 units of padding. A click or drag recenters the canvas; its bounds are frozen while it is dragged, so the map stands still. |
| Zoom controls | `ZoomControls`, `stepZoom` (`canvas`) | – | Buttons − and +, which step the zoom by 0.1, the percentage and Reset. |
| Block | `editor/blocks/`, `coreBlocks` | node types in a text box's `content` | A TipTap node in group `block`. Avoid: template (old folder `templates/`). |
| Live block | `tocBlock`, `pageHierarchyBlock` | see the next two rows | Atom block whose list is computed on render; no snapshot is saved. |
| Table of contents | `tocBlock` | node `tocBlock`, no attrs | Live list of the headings in its own text box. It rebuilds only when the list of heading levels and texts changes; a click looks the heading up again, so a moved heading still scrolls. German: Inhaltsverzeichnis. |
| Page hierarchy | `pageHierarchyBlock` | node `pageHierarchyBlock`: `kind`, `targetId` | Live list of a chapter's pages or a page's subpages. German: Seitenhierarchie. |
| Callout | `callout`, `CALLOUT_VARIANTS`, `parseCalloutVariant` | node `callout`, attr `variant` | Variants `info`, `note`, `warning`, `error`, labelled Info, Note, Warning, Error. `parseCalloutVariant` turns anything else into `info`, when pasted HTML is read and when a stored value is drawn; the stored value is not changed. German: Hinweis, Warnung, Fehler. |
| Table | `table`, `TableWithControls`, `attachBoundaryControls`, `insertionAt`, `cellCoordinates` | nodes `table`, `tableRow`, `tableHeader`, `tableCell` | TipTap table with hover "+" controls at every row and column boundary and a context menu (`openContextMenu`). The controls are placed with `offsetLeft`/`offsetTop` when the pointer enters the table, so the canvas zoom does not matter. The target cell of a command is found with `posAtDOM` and `TableMap`, so merged cells count right. Deleting the last row or column deletes the table. |
| Slash command | `SlashCommand`, `SlashMenu` | – | The `/` menu in a text box. Suggestion mounts and positions `SlashMenu` (`props.mount`, Floating UI); `onExit` is the only place that removes it. Avoid: backslash command. |
| Slash item | `SlashItem`, `filterSlashItems` | – | One entry of the slash menu; `run(editor, range)` replaces the command range, mostly through `replaceRangeWith`. Each block file exports its items next to its node. Avoid: `TemplateCommand`, `getTemplateCommands`. |
| Editor feature | `EditorFeature`, `editorFeatures` | – | Adds extensions and slash items; a fixed list (`coreBlocks`, `financeFeature`), not a plugin system. `app/editorFeatures.ts` lists them and reaches each text box through `ContentArea`, `CanvasView` and `TextBox` as the prop `features`; `buildExtensions(features)` builds the extension list. `finance/feature.ts` is the only place where the editor and finance meet. `app/editorFeatures.ts` picks `financeFeature` or `financePlaceholderFeature` by `FEATURE_FINANCE`. |
| Jump link | `renderLinkList`, `JUMP_LINK_CLASS` (CSS `jump-link`) | – | Entry of a live block that scrolls to a heading or opens a page. Not a hyperlink. Avoid: template link. |
| Link list | `renderLinkList`, `renderLinkListBlock`, `LinkListItem`, `UNTITLED_LABEL` (CSS `link-list-*`) | – | The list DOM that both live blocks share: items of `label`, `depth` and `onClick`; an empty label shows as Untitled. Avoid: `toc-block-*`. |
| Hyperlink | `LinkPopover`, `applyLinkInput`, `allowedLinkUrl`, `isAllowedExternalUrl`, `normalizeLinkInput` (`@shared/links`) | mark `link`, attr `href` | Link to an external URL; only `http:`, `https:`, `mailto:` open. A URL with whitespace, a control character or a backslash anywhere is rejected (the URL parser silently drops tabs and newlines and reads a backslash as a slash, so the dialog would show another address than the one that opens), and so is a path that starts with `/` or `\`. `allowedLinkUrl(input)` is the one helper that normalizes and checks; main applies the same `isAllowedExternalUrl` again. The popover takes URLs only: input without a scheme gets `https://`, an empty input removes the link, and anything outside the allowlist is rejected with a message and changes nothing. A link to a local file is not offered. Avoid: file link. |
| Link guard | `linkGuard`, `linkGuardPlugin` (`editor/links`) | – | Editor plugin that catches every click on `a[href]` (and a middle click), editable or not, calls `preventDefault` and passes the `href` attribute as written to `useLinkStore.requestOpen`. It listens to the DOM `click`, because ProseMirror's `handleClick` runs on `mouseup` and cannot stop a native navigation. TipTap's own opening stays off (`openOnClick: false`). Avoid: `ExternalLinkGuard`. |
| External link confirmation | `LinkConfirmDialog`, `useLinkStore`, `requestOpen`, `confirmOpen` | localStorage `mynote-trust-external-links` | `requestOpen` normalizes the `href` and checks the allowlist first: a blocked URL shows the error toast "This link type cannot be opened." and never reaches the dialog. A trusted URL opens at once; any other waits for the dialog "Open External Link" (a `Modal`), and `confirmOpen` checks again that exactly the string the dialog showed passes, then opens it. A second link while one is pending replaces it. "Don't ask again" stores `true`. Avoid: `ExternalLinkGuard`, `ExternalLinkConfirmDialog`, `useExternalLinkStore`. |
| Formatting toolbar | `Toolbar`, `toolbarState`, `ToolbarState` (`editor`) | – | Buttons above the focused text box: bold, italic, underline, strikethrough, headings 1 to 3, bullet and ordered list, code block, link. `toolbarState` is the `useEditorState` selector that gives each button its active state, because `useEditor` does not re-render on every transaction. |
| Link open failure | `onLinkOpenFailed` (`editor`) | – | Main found no browser for a confirmed hyperlink and copied the URL to the clipboard. App shows the toast "No browser available — link copied to clipboard: <url>". |
| Legacy node | `legacyNodes` | `templateLink`: `kind`, `targetId`, `label` | Load-only; never remove a registered node type, the page would load empty. Heading attr `id` is legacy too: the schema no longer has it, so it is dropped on load. A `templateLink` of kind `heading` does nothing on click. |
| Content check | `useNoteEditor`, `noteEditorOptions`, `onContentError` (`editor`) | – | Every text box loads with TipTap's `enableContentCheck`. A node no feature registers makes the box read-only, shows "Read-only: this text box contains content this version cannot display. The stored content stays unchanged." and commits no content, so the file keeps it; moving or resizing the box still works and keeps the stored content. |

## Finance

| Term (UI) | Code | Files / persisted | Notes |
|---|---|---|---|
| Ledger | `financeLedger`, `FinanceLedgerNode`, `LedgerBlock` | node attr `ledgerId`, written as `data-ledger-id` in HTML; `finance/ledgers/<id>.csv`, `finance/ledgers/<id>.meta.json` (`name`, `currencySymbol`, `columns`) | A list of entries, one CSV per ledger. Avoid: finance table, source. |
| Ledger column | `LEDGER_COLUMNS`, `ColumnConfig`, `resolveColumn`, `applyColumnFormat`, `alignClass`, `resolveColumns`, `formatNumber`, `clampDecimals`, `parseDecimals`, `resizedColumnWidth`, `startWidthDrag`, `MAX_DECIMALS`, `MAX_EDIT_DECIMALS`, `MIN_COLUMN_WIDTH` (`finance/ledger/columns.ts`) | `columns` in the meta, keyed `date`, `type`, `amount`, `account`, `category`, `topic`, `tags` | Display settings of a column: `align`, `width` and, for `amount` only, a `number` format. `resolveColumn(id, stored, currency)` gives what a column is drawn with and fills the default amount format; old files may still carry `type` or `date` under a column, which are ignored. Keys differ from the CSV header names. `formatNumber` clamps `decimals` to 0..20 itself, so no stored value can make it throw; the column settings offer 0..4 (`parseDecimals` clamps typed text and gives `null` for text that is no number). The width is kept in local state while the pointer drags (`resizedColumnWidth`: start width plus the distance divided by the canvas zoom, at least 48 px) and is saved once on release (`startWidthDrag(...).finish()`), only if it differs from the start width; `Auto width` saves the column without `width`. |
| Ledger UI | `LedgerBlock`, `LedgerToolbar`, `LedgerTable`, `EntryCells`, `BalanceFooter`, `ColumnConfigPopover` (`finance/ledger/`), `reportFailure` (`finance/`) | – | `LedgerBlock` only composes: title, `LedgerToolbar` (Import, Export, Reference data, Delete), the error boxes, `LedgerTable` and `BalanceFooter`. It reads its ledger with `ledgerOf`, and a `ledgerId` attribute that is no string counts as `''`. A `loadError` shows one red box (the message and "This ledger was not changed.") and no table, no draft row and only Delete in the toolbar. A `saveError` shows "Not saved: <message>" above the table until the next successful write. A `referenceError` shows "Accounts and categories could not be read: <message>. They are not changed." and disables the account and category pickers and the Save of the reference data dialog. `LedgerTable` holds the header (column width drag, column settings), the rows (50 per page above 100 rows), the draft row and `+ Add entry`; `EntryCells` renders the seven cells of a stored row and of the draft row. Delete in `LedgerToolbar` is the only place in the app that deletes a ledger: `ConfirmDialog` (`deleteDialog` gives its texts), then `removeLedgerBlock(ledgerId, onDeleted)` (`ledger/removal.ts`), which calls `deleteLedger` and then `deleteNode`. A block without a valid ledger id has no file: the dialog says "Remove block" with the button "Remove", `deleteLedger` is never called, and a rejected deletion keeps the block. While the reference data cannot be read, an entry with an account the list does not know shows "(unavailable)" instead of "(deleted account)". `reportFailure(task)` shows a rejected store action as an error toast, so no rejection stays unhandled (`notebook/store.ts` has a different helper of this name: NAMING-CHECK). |
| Commit input | `CommitInput`, `resolveCommit`, `Validate`, `positiveAmount`, `signedAmount`, `tagList`, `settleEdit`, `beginEdit`, `typeText`, `activeEdit` (`finance/ledger/CommitInput.tsx`) | – | A text input that stores nothing while typing: it keeps the raw text while focused and shows the formatted stored value otherwise (`format`). Blur or Enter runs `resolveCommit(raw, stored, validate)`, which gives `unchanged`, `commit` (with the normalized text) or `invalid` (with a message). An invalid text is never committed: it stays visible with the message (`role="alert"`) until the user edits again, presses Escape (back to the stored text) or the stored value changes. `positiveAmount` and `signedAmount` use `normalizeAmount`, `tagList` uses `parseTags`. `onInvalidChange` tells a parent that an input holds such a text, so the reference data dialog disables Save. A date input and a `select` commit on change instead, and a cleared date is ignored. While an edit is active the input listens for `beforeunload` (`watchUnload`, capture phase, so it runs before the canvas content store checks for unsent writes); `unloadCommit` commits a valid, changed text and never an invalid one, so closing the window with the cursor still in a field loses nothing. |
| Entry draft | `EntryDraft` (`finance/model.ts`), `emptyDraft`, `draftProblem`, `addDraft` (`finance/ledger/draft.ts`) | – | An entry without `id` and `pos`, also the row under the table. `emptyDraft(now?)` starts as an expense of today. `draftProblem(draft, { amountInvalid })` says what is missing before `+ Add entry` works (an amount above 0 and an account) and refuses with "Fix the amount first." while the amount field shows an invalid text, because the draft then still holds the last valid amount; `addDraft(ledgerId, draft, amountInvalid)` adds the draft or gives that hint, and the table shows it inline. |
| Pager | `pageWindow`, `pagerLabel`, `PAGE_SIZE`, `PAGINATE_THRESHOLD` (`finance/ledger/pager.ts`) | – | Above 100 rows the table shows 50 per page, newest first; the label reads `Page 1/3 · 120 rows`. |
| Error box | `ErrorBox` (`finance/ErrorBox.tsx`) | – | Red block with `role="alert"` for the errors that stay visible: a ledger block, the reference data dialog and a failed import in `ImportDialog`. A toast is for a failed action. |
| Live store | `liveStore` (`finance/store.testing.ts`) | – | Test helper: `renderToString` gives a zustand hook the initial state of its store, so a component test wraps the hook to read the current state. |
| Statistics block | `financeStats`, `FinanceStatsNode`, `StatisticsBlock` (`finance/statistics/`), `parseStatsSettings`, `StatsSettings`, `loadLedgerChoices` | node attrs `ledgerId`, `mode`, `from`, `to`, `categoryFocus`, `tagFilter` (HTML: `data-ledger-id`, `data-mode`, `data-from`, `data-to`, `data-category-focus`, `data-tag-filter` as JSON text) | Totals and charts of one ledger, read-only: it cannot delete a ledger (only `LedgerToolbar` can). The attributes are the persisted format and never change; the period preset (`This month`, `This year`, `Custom range…`) is local state of the block and starts on `This month`. `parseStatsSettings` gives each attribute the type the block relies on (a value of the wrong type gives its default), so a hostile or empty `ledgerId` never throws: the block reads its ledger with `ledgerOf` and shows `loadError` as "This ledger could not be read: <message>" and `referenceError` as "Accounts could not be read: <message>. The balances are not shown." in an `ErrorBox`. `loadLedgerChoices(listLedgers)` never rejects; a failed listing shows "The ledger list could not be read: <message>". The entries are filtered once (range and `tagFilter`); `tagFilter` has no UI but is persisted and honoured. Avoid: source. |
| Statistics period | `presetRange(preset, today, custom)`, `Preset` (`finance/statistics/stats.ts`) | – | The date range of a preset: `month` ends on the real last day of the month of `today` (`2024-02-10` gives `2024-02-29`), `year` is 1 January to 31 December, `custom` is the stored `from`/`to` where an empty side stays open (`0000-01-01`, `9999-12-31`). |
| Category key | `breakdownByCategory`, `CategoryBucket` (`finance/statistics/stats.ts`) | – | The entries without a category have the key `''`; the UI shows "(no category)". Buckets sort by expense, highest first. |
| Chart | `Bars`, `Pie`, `Line`, `EmptyChart`, `ChartDatum`, `pieSlices`, `lineY` (`finance/statistics/charts.tsx`) | – | Plain SVG charts without a library. `Pie` with an `innerRadius` is a donut (the statistics block draws income and expenses that way, with the net amount as `centerLabel`). `pieSlices(data)` drops zero and negative values and gives each slice a `start` and an `angle`; the angles add up to 360, one slice is a full circle. `lineY(value, maxAbs, height)` maps `[-maxAbs, maxAbs]` onto `[height, 0]` (the middle when `maxAbs` is not positive), so deficit months stay inside the picture; `Line` draws the zero line and shows a single month as a flat segment. A plain pie has the radius 40, a donut the ring from 32 to 48; a slice of 359.9 degrees or more is drawn as a whole circle. `EmptyChart` shows "No data". |
| Finance feature | `financeFeature` (`finance/feature.ts`) | slash items `ledger`, `statistics` | The editor feature of the finance module: the two nodes with their React views and the slash items `Ledger (income and expenses)` and `Statistics`. The ledger item makes the id with `newId()`, inserts the block at once and creates the ledger (`createLedger(id, 'New ledger')`) in the background; a failure shows as an error toast (`reportFailure`) and the block stays. |
| Entry | `Entry` | one CSV row; header `id,pos,date,type,amount,accountId,categoryPath,topic,tags,referenceLink` | One income or expense. `type` is `income` or `expense`. German: Buchung. |
| Account | `Account` | `finance/accounts.json`: `id`, `name`, `openingBalance` | Shared by all ledgers of a notebook folder. German: Konto. |
| Balance | `balance` (identifier root) | `openingBalance` on the account | Opening balance + income - expense of an account. `computeAccountBalances(entries, accounts)` gives one `AccountBalance` (`openingCents`, `flowCents`, `balanceCents`) per account; the statistics block passes the entries of its period, `BalanceFooter` all entries of the ledger. German: Saldo; Startsaldo = opening balance. Avoid: `saldo` in identifiers. |
| Category path | `categoryPath`, `flattenCategories` | CSV column `categoryPath`; `finance/categories.json`: `name`, `children` | `/` separates levels, e.g. `Food/Groceries`; empty = no category. `flattenCategories` lists every path prefix of the tree (`Food`, `Food/Groceries`). `cleanCategoryPath` trims each segment and drops empty ones (`' Food / Groceries '` gives `Food/Groceries`); import and `mergeCategoryPaths` both use it. German: Kategorie. Avoid: `kat`, `unter`. |
| Canonical amount | `normalizeAmount`, `parseMoneyToCents`, `formatCents` (`finance/model.ts`) | `amount` in the CSV, `openingBalance` on the account | Dot-decimal text with two decimals, e.g. `12.50`, `-3.00`. `normalizeAmount(input, allowNegative)` is the strict gate for typed or imported amounts: it accepts `,` or `.` as the one decimal separator, no thousands grouping, rounds half up and gives `null` for anything else (and for zero unless negatives are allowed). `parseMoneyToCents` is the lenient reader of stored text (unparsable gives 0). |
| Tags | `tags`, `parseTags` | CSV column `tags`, joined with `;` | Free labels of an entry, typed with `,` or `;`. |
| Receipt link | `referenceLink`, `pickReceipt`, `RECEIPT_FILTERS` (`finance/ledger/receipt.ts`) | CSV column `referenceLink` | File path of a receipt on an entry. German: Beleg. Avoid: invoice. Unrelated to Reference data. `pickReceipt()` opens the file dialog through `pickFile` (`storage`) with the filter name `Receipts` (`pdf`, `png`, `jpg`, `jpeg`) and gives the path or `null`; the button title is "Link receipt". A link can be set, not opened or cleared (follow-up). |
| Reference data | `ReferenceDataDialog`, `ReferenceDataEditor`, `cleanAccounts`, `cleanCategories`, `cleanCategoryName`, `saveReferenceData`, `newAccount`, `newCategory`, `referenceError` | `finance/accounts.json`, `finance/categories.json` | Accounts plus categories, shared by all ledgers. A corrupt or wrongly shaped file sets `referenceError` and blocks every write to both files; `loadReferenceData` clears it once both are readable. `ensureAccounts`, `ensureCategories`, `saveAccounts` and `saveCategories` read the files first and reject while it is set. The dialog (`Modal`, size `lg`, title "Reference data") reads the files when it opens and edits copies. Opening balances go through `CommitInput` with `normalizeAmount(raw, true)`, and Save stays disabled while one holds a text that is no number. `saveReferenceData(accounts, categories)` cleans both lists first, then runs `saveAccounts` and `saveCategories`, and gives the error message or `null`: it drops accounts and categories whose trimmed name is empty, trims names and removes `/` from category names, but refuses with "A category needs a name." (nothing is written) when a category without a name has subcategories. A failure shows inline and the dialog stays open. A new account id comes from `newId()` and a new category is named `New`. Duplicate names and renaming migration are follow-ups. |
| Finance store | `useFinanceStore`, `LedgerState`, `ledgerOf`, `nextPos`, `mergeAccounts`, `mergeCategoryPaths` (`finance/store.ts`) | – | State: `ledgers` (by ledger id), `accounts`, `categories`, `referenceError`. A ledger holds `meta`, `entries`, `saveError` and `loadError`. All file access goes through `storage`; a write is queued per path and the newest text wins. The meta file is written only when its text changed. `ledgerOf` looks a ledger up with `Object.hasOwn`, because `constructor` is a valid ledger id. `ensureAccounts` gives a `Map` from trimmed name to account id (a plain object breaks on `__proto__`). Reference data operations (`loadReferenceData`, `ensure*`, `save*`) run one after the other, so none works on data another is about to change. The meta is skipped only when its text equals the last text queued for that ledger; a failed meta write is forgotten and retried. An update is refused while `deleteLedger` runs. `createLedger(id, name)` takes its id from the caller; `deleteLedger` waits for queued writes first. Avoid: `loaded`. |
| Save error | `saveError` (`LedgerState`) | – | The message of the last failed write of a ledger, e.g. EBUSY while Excel holds the CSV. The change stays in the state and the file on disk stays as it was (main writes atomically); the next successful write clears it. Entry and column actions do not reject for it. |
| Load error | `loadError` (`LedgerState`) | – | The files of a ledger could not be read: corrupt `meta.json`, a CSV that is not a ledger file (other header, or a row without 10 cells), an unreadable file or an invalid ledger id. The ledger stays empty and every write to it is refused, so the files are never overwritten. A later `loadLedger` clears it once the files are readable. |
| Finance paths | `FINANCE_DIR`, `ACCOUNTS_PATH`, `CATEGORIES_PATH`, `ledgerCsvPath`, `ledgerMetaPath`, `checkLedgerId` (`finance/paths.ts`) | `finance/accounts.json`, `finance/categories.json`, `finance/ledgers/<id>.csv` and `.meta.json` | The one place that builds a finance file path. `checkLedgerId` throws `Invalid ledger id: <id>` unless the id passes `isValidId`, so an id such as `../x` never reaches a file. |
| Finance validators | `parseAccounts`, `parseCategories`, `parseLedgerMeta`, `MAX_CATEGORY_DEPTH` (`finance/validate.ts`) | – | The load checks that `readJson` runs, and the check before every save of accounts, categories and columns, so the app never writes a file it would reject. Accounts: a list of records with a non-empty string `id`, string `name` and `openingBalance`, no repeated id. Categories: a tree of records with a string `name` and a list `children`, at most 32 levels; names are not checked. Meta: string `name` and `currencySymbol`; per column `align` (`left`, `center`, `right`), `width` above 0 and a `number` format whose `decimals` is cut to a whole number from 0 to 20 (v0.1.x never limited it; a non-number is corrupt). A wrong type anywhere makes the file corrupt; keys the type no longer has (`type`, `date`) are dropped. |
| Transfer | `finance/transfer` (`transfer.ts`: `importLedgerCsv`, `importMoneyManager`, `exportLedgerCsv`, `TransferResult`; `exportFileName`; `ImportDialog`) | – | Import and export of ledger data (ledger CSV, Money Manager `.xlsx`). Not a bank transfer; those Money Manager rows are skipped. `transfer.ts` is the only file of `finance` besides the rest of `transfer/` that calls `window.api`. An import gives `{ imported, skipped, createdAccounts, createdCategories }`, or `null` when the user cancelled the file dialog; the counts of created accounts and categories compare the files before and after. The store reports a failed write in `saveError` and does not reject, so an import reads `saveError` afterwards and throws `Entries were added but could not be saved (<saveError>). Do not import again: ...`, because the entries stay in the ledger and the next successful write saves them; an unreadable or unloaded ledger is refused before anything is added. The dialog shows the error message as it is, in the red error style. `ImportDialog` is UI only. |
| Ledger CSV | `LEDGER_HEADER`, `serializeLedgerCsv`, `loadLedgerCsv`, `parseLedgerCsv` (`finance/ledgerCsv.ts`); `parseCsv`, `serializeCsv` (`finance/csv.ts`) | `finance/ledgers/<id>.csv`; header `id,pos,date,type,amount,accountId,categoryPath,topic,tags,referenceLink` | `csv.ts` is the generic RFC-4180 codec, `ledgerCsv.ts` maps ledger rows. `loadLedgerCsv` reads a stored ledger: values stay as stored (v0.1.x amounts such as `12,5`), no row is dropped, but another header or a row without 10 cells throws, which ends as the ledger's `loadError`. `parseLedgerCsv` reads a file picked for import and is strict: a BOM is dropped, the header must match (else `This is not a MyNote ledger CSV`), and a row needs a real date `YYYY-MM-DD`, type `income` or `expense`, an amount `normalizeAmount` accepts and 10 cells, otherwise it counts as `skipped`; blank lines are ignored. Import gives no `id` and `pos`. |
| Skipped | `skipped` (`LedgerImport`, `MoneyManagerImport`, `TransferResult`) | – | Rows of an import file that carry data but were not imported: invalid, or a Money Manager transfer. Blank rows are not counted. |
| Money Manager values | `MONEY_MANAGER` | – | `Einkommen` = income, `Ausgabe` = expense in the `.xlsx`. Data constants, not UI text, like the header words `Datum`, `Konto`, `Kategorie`, `Unterkategorie`, `Notiz` and `Einnahmen/Ausgaben` in `finance/transfer/moneyManager.ts`. `mapMoneyManager` throws `This is not a Money Manager export` when the header differs (the amount header is the currency code, any non-empty text) and reads dates only as Excel serials (`excelSerialToISO`); a text date skips the row. |
| Locale | `LOCALE`, `DEFAULT_CURRENCY` | `currencySymbol` in the ledger meta | `de-DE` number and date format, defined once in `finance/model.ts`. |

## Platform

| Term (UI) | Code | Files / persisted | Notes |
|---|---|---|---|
| IPC channel | `IPC` (`@shared/ipc`) | – | Named `namespace:camelCase`, e.g. `files:readText`. Avoid: `fs:readFile`, `dialog:openDirectory`, `external-link-open-failed`. |
| Preload API | `window.api`, `MyNoteApi` | – | The only object preload exposes. Avoid: `window.electron`. |
| Folder-relative path | `joinPath` (renderer), `resolveInRoot` (main) | – | Path as sent over IPC: relative to the notebook folder, `/`-separated. Main rejects anything outside. |
| Write queue | `writeText`, `writeJson`, `flushWrites`, `hasUnsentWrites` (`storage`) | – | Per path, one write in flight and the newest pending text wins. `readText` and `readJson` wait for the writes queued for the same path, so a read sees their text. `flushWrites` waits for the writes sent or queued so far; `hasUnsentWrites` is true while text waits behind an in-flight write and has not reached main. |
| Corrupt file | `CorruptFileError` (`storage`) | – | Thrown by `readJson` when a file exists but holds bad JSON or fails its parser. Message `<path>: <reason>`; `cause` holds the original error. A missing file is not corrupt (`null`). |
| Value check | `isRecord`, `describeValue`, `fieldsOf`, `textOf` (`storage`), `messageOf` (`@shared/errors`) | – | The helpers every parser and error report shares. `isRecord` is true for a plain object only (no array, no `null`). `fieldsOf(value, where)` gives that record or throws `<where> must be an object`; `textOf(fields, key, where)` gives a string field or throws `<where>: <key> must be a string`. `describeValue` shows a parsed value in an error message, cut after 40 characters. `messageOf` is the text of a caught value. |
| Intent | `files.importText`, `files.exportText`, `xlsx.importSheet` | – | Main-side dialog plus read or write in one call, so no external path crosses IPC. |
| App settings | `AppSettings` | `<userData>/settings.json`: `autoUpdateEnabled` | Read by main at startup. `userData` is Electron's app-data folder, not the notebook folder. |
| Settings dialog | `SettingsDialog`, `SettingsButton` (`settings`) | – | Opened by the ⚙️ button and mounted only while open. Shows the app settings and the manual update check; a failed settings read or save shows as error text in the dialog. |
| Theme | `useThemeStore`, `ThemeToggle`, `applyThemeBeforeFirstPaint`, `readStoredTheme`, `THEME_STORAGE_KEY` (`settings`) | localStorage `mynote-theme` (`dark` or `light`) | Per device; not part of the app settings. Nothing stored or `dark` means dark; any other value means light. The class `dark` on `<html>` switches the look; `main.tsx` sets it before the first render. |
| Module | `@renderer/<module>` | `<module>/index.ts` | `ui`, `storage`, `settings`, `notebook`, `editor`, `canvas`, `finance`, `app`. The barrel is the public API; no deep imports. |
| Dialog | `Modal`, `ConfirmDialog`, `TextInputDialog` (`ui`) | – | Rendered into `document.body` and mounted only while open. Escape closes the topmost dialog wherever the focus is, and an auto-repeated Escape (a held key, `KeyboardEvent.repeat`) is ignored, so a held key closes only one dialog; a backdrop click closes it too (`onClose`; `onCancel` in the two dialogs, but not while `ConfirmDialog` is `busy`). `pointerdown`, `mousedown`, `click`, `dblclick`, `contextmenu`, `keydown` and `wheel` stop at the modal, so the opener never sees them. Avoid: `window.confirm`, `alert`, `prompt`. |
| Context menu | `openContextMenu`, `closeContextMenu`, `ContextMenuItem`, `ContextMenuHost` (`ui`; store `useContextMenuStore`) | – | One menu at a time, opened at a point and kept inside the window (`clampToViewport`). Closes on an outside pointerdown, Escape, scroll or window blur. App mounts the host. The sidebar and the table use it; its items are plain `onSelect` callbacks. |
| Toast | `notify`, `Toaster` (`ui`; store `useToastStore`) | – | Short message at the bottom of the window. `info` hides after 4 s; `error` stays until dismissed. A message equal in text and kind to a toast still shown is dropped. App mounts the `Toaster`. |
| Button style | `buttonClass` (`ui`) | – | `primary`, `secondary`, `danger`, `ghost`: the look of the dialog buttons. |
| Pointer drag | `usePointerDrag` (`ui`) | – | Drag with pointer capture. Reports CSS-pixel deltas since the pointerdown; a zoomed caller divides them by the zoom. |
| App shell | `App`, `ContentArea`, `contentKey` (`app`) | – | `App` switches between the welcome screen (no `dataRoot`) and the workspace, and mounts the hosts: link confirmation dialog, context menu, toasts. It reads `dataRoot` only. `ContentArea` alone reads `selection` and keys the canvas by `contentKey` (`<kind>:<id>`), so every content gets a fresh canvas. |
| Error boundary | `ErrorBoundary` (`app`) | – | Wraps `App` in `main.tsx`. A render error shows "Something went wrong", the message and a Reload button instead of a blank window. It does not catch errors in event handlers or async code. |
